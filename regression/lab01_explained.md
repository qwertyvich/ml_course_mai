# Разбор лабораторной № 1: обычная линейная регрессия

Это отдельный материал для понимания кода и подготовки к защите. Отчёт для сдачи — [lab01.ipynb](lab01.ipynb).
Актуальная работа использует **только красное вино** и основную **обычную LinearRegression**.
Здесь объяснена именно эта версия. Код ниже соответствует вычислительным ячейкам текущего ноутбука.

## Суть задачи и результата

Одна строка таблицы — одно вино, 11 столбцов описывают химические свойства. Это вход X.
Оценка экспертов quality — ответ y, который модель должна предсказывать для новых вин.
Во время обучения известны X и y. При predict передаются только признаки: оценка нового вина ещё неизвестна.

В исходном CSV 1 599 строк и 12 столбцов: 11 признаков и цель. После удаления 240 повторных строк
остаётся 1 359 уникальных наблюдений. X имеет размер 1 359 × 11, y содержит 1 359 оценок.
Train содержит 1 087 вин, test — 272. Способ разбиения и seed заранее зафиксированы.

Главный результат: обычная линейная регрессия получила **RMSE = 0.6565**, **MAE = 0.5041** на локальном test.
Средняя CV RMSE на пяти фолдах train — **0.6684**. Порог задания — 0.70, а не 70.
Лес и бустинг рассчитаны для сравнения; их прогнозы не входят в итоговый прогноз линейной модели.

| Модель | Test RMSE | Test MAE |
|---|---:|---:|
| Константный baseline | 0.8443 | 0.7049 |
| **Linear Regression — основная** | **0.6565** | **0.5041** |
| Random Forest — сравнение | 0.6179 | 0.4693 |
| Gradient Boosting — сравнение | 0.6137 | 0.4693 |

У ансамблей ошибка меньше, однако требование получить результат линейной регрессией выполнено
отдельно и независимо от их прогнозов. Здесь не выбирается лес под названием линейной модели.

## Что означают основные действия

- Создать `LinearRegression()` — получить объект с реализацией алгоритма, ещё без обучения на винах.
- Вызвать `fit(X_train, y_train)` — подобрать коэффициенты по известным примерам.
- Вызвать `predict(X_test)` — применить сохранённые коэффициенты к признакам других вин.
- `fit` у scaler вычисляет статистики признаков, `transform` применяет ранее вычисленные статистики.
- `Pipeline` объединяет scaler и регрессию в единую последовательность.
- CV проверяет фиксированную модель на сменяющихся частях train. Финальный test остаётся отдельно.

Дальнейший разбор следует порядку ноутбука.


`isna()` создаёт таблицу True/False: True соответствует пропуску. Два последовательных sum
сначала считают пропуски в каждом столбце, затем суммируют по столбцам. Здесь итог равен нулю.
`dtypes` показывает числовые типы исходных столбцов.

`duplicated()` отмечает повторные появления полностью одинаковых строк. Таких строк 240.
`drop_duplicates()` оставляет первое появление каждой уникальной строки.
`reset_index(drop=True)` заново нумерует строки и не добавляет старую нумерацию как новый столбец.
Получается 1 359 наблюдений. Эта схема оценивает качество на уникальных строках.

Цель отделяется: X содержит `data` без столбца quality, y — только quality. Если оставить ответ в X,
возникнет утечка: при настоящем прогнозе этот ответ неизвестен. Индекс строки также не является признаком.

Проверяется отсутствие повторов и по одним X без цели. Их нет, поэтому обычное случайное разбиение
не разделит одинаковые наборы признаков между train и test. `assert` останавливает выполнение при нарушении
предположения; он сам не исправляет данные.

Отдельного постоянного X_val в работе нет. Validation по очереди становится каждый из пяти фолдов

После CV итоговая модель обучается на всех 1 087 объектах, затем проверяется на 272 тестовых.

Нельзя выбирать параметры после каждого взгляда на test: это подстроит решение под него.
Низкая обучающая ошибка сама по себе не подтверждает способность работать на новых винах.

## Константный baseline и метрики

```python
baseline = DummyRegressor(strategy='mean')
baseline.fit(X_train, y_train)
print(f'Константа baseline: {y_train.mean():.4f}')
```

`DummyRegressor(strategy='mean')` при fit сохраняет среднее y_train — примерно 5.6366.
Он выдаёт одну константу независимо от признаков нового вина.
Среднее минимизирует сумму квадратов отклонений от постоянного прогноза;
извлечение корня не меняет положение минимума. Поэтому оно оптимально для константного baseline по RMSE.
Для MAE оптимальной константой была бы медиана.

MAE — среднее абсолютное отклонение в баллах качества. MSE — средний квадрат отклонения,
RMSE — квадратный корень из MSE. Например, при ошибках 0, −1, +2 получаем
MAE=(0+1+2)/3=1, MSE=(0+1+4)/3=5/3, RMSE≈1.291.
RMSE сильнее учитывает крупные промахи. Ошибки разных знаков в этих метриках не сокращаются.
Среднее ошибки со знаком −2 и +2 равно нулю, но оба прогноза неверны.

На test baseline получил RMSE 0.8443 и MAE 0.7049. Это исходная точка сравнения,
полученная вообще без использования химического состава.

## Основная линейная модель и сравнительные ансамбли

```python
candidates = {
    'Baseline': DummyRegressor(strategy='mean'),
    'Linear Regression': make_pipeline(StandardScaler(), LinearRegression()),
    'Random Forest': RandomForestRegressor(
        n_estimators=500, max_features=0.5,
        random_state=RANDOM_STATE, n_jobs=-1
    ),
    'Gradient Boosting': GradientBoostingRegressor(
        n_estimators=200, learning_rate=0.05, max_depth=3,
        min_samples_leaf=20, subsample=0.8, random_state=RANDOM_STATE
    ),
}
```

Основной кандидат — `make_pipeline(StandardScaler(), LinearRegression())`.
Регрессия вычисляет y_hat = w0 + w1*z1 + ... + w11*z11. Коэффициенты подбираются обычным методом
наименьших квадратов: минимизируется сумма квадратов ошибок. Библиотека использует численные методы
линейной алгебры, не ручной перебор всех возможных весов.

Scaler отдельно для каждого столбца вычисляет μ и σ на обучающих данных, затем z=(x−μ)/σ.
Пример: train `[10,12]` → μ=11, σ=1 → `[-1,1]`. Проверочное значение 14 преобразуется в 3
по тем же μ и σ. На test scaler заново не обучается.
StandardScaler использует σ с ddof=0; pandas.describe показывает стандартное отклонение с ddof=1.

Pipeline при fit сначала обучает scaler и преобразует X, затем обучает LinearRegression.
При predict использует сохранённый transform и сохранённые веса. В predict передаётся исходный X_test:
второе ручное масштабирование было бы ошибкой. Обычная линейная регрессия здесь не имеет регуляризации,
полиномов или скрытого леса. Стандартизация меняет единицы признаков и помогает интерпретации весов.

Сравнительный лес усредняет 500 деревьев. `max_features=0.5` разрешает случайное подмножество признаков
при поиске разбиения узла; это не удаление половины столбцов из задачи. `n_jobs=-1` ускоряет вычисления.
Бустинг добавляет 200 деревьев последовательно с шагом 0.05. При квадратичной потере новые деревья
предсказывают поправки y−текущий прогноз; эти поправки складываются. Глубина 3, лист не меньше 20,
подвыборка каждого шага — 80% обучающих строк. Эти ансамбли только сравниваются с основной моделью.

## Пять запусков кросс-валидации

```python
cv = KFold(n_splits=5, shuffle=True, random_state=RANDOM_STATE)
cv_rows = []

for name, model in candidates.items():
    scores = cross_validate(
        model, X_train, y_train, cv=cv,
        scoring={'RMSE': 'neg_root_mean_squared_error',
                 'MAE': 'neg_mean_absolute_error'},
        return_train_score=True,
        n_jobs=1,
    )
    cv_rows.append({
        'Вариант': name,
        'CV RMSE': -scores['test_RMSE'].mean(),
        'CV MAE': -scores['test_MAE'].mean(),
        'CV std': scores['test_RMSE'].std(),
        'Train RMSE': -scores['train_RMSE'].mean(),
    })

cv_table = pd.DataFrame(cv_rows).set_index('Вариант')
display(cv_table.round(4))
```

`KFold(5, shuffle=True, random_state=42)` создаёт одинаковые фолды для всех кандидатов.
Внутри train из 1 087 объектов размеры проверочных фолдов — 218, 218, 217, 217 и 217.
На каждом запуске обучаются на остальных четырёх частях.
`cross_validate` создаёт новые копии модели; для Pipeline копируется также scaler.
Поэтому scaler вычисляет статистики только по обучению своего фолда.

В scoring используется отрицательная ошибка: sklearn по соглашению максимизирует scorer.
Поэтому −0.6 лучше −0.7. Перед выводом отчёта минус возвращается.
`scores['test_RMSE']` содержит пять отрицательных проверочных метрик.
Слово test внутри этого интерфейса означает validation-фолд из X_train,
а не отложенный X_test, который вообще не передан этой функции.

`.mean()` усредняет пять чисел, `.std()` показывает их разброс. Разброс не является доверительным интервалом.
`return_train_score=True` дополнительно оценивает обучение каждого запуска.
`append` складывает словари результатов в список; DataFrame превращает его в итоговую таблицу.

У линейной модели CV RMSE=0.6684, CV MAE=0.5175, стандартное отклонение RMSE=0.0267.
Её Train RMSE≈0.6573 близка к CV: большого разрыва обучения и проверки здесь нет.
У леса Train RMSE≈0.2421 при CV RMSE≈0.6557; низкую обучающую ошибку нельзя считать качеством на новых объектах.

## Итоговое обучение и сохранение линейной модели

```python
fitted_models = {}
test_predictions = {}
test_rows = []

for name, variant in selected_variants.items():
    model = clone(candidates[variant])
    model.fit(X_train, y_train)
    prediction = model.predict(X_test)
    fitted_models[name] = model
    test_predictions[name] = prediction
    test_rows.append({
        'Модель': name,
        'RMSE': root_mean_squared_error(y_test, prediction),
        'MAE': mean_absolute_error(y_test, prediction),
    })

results = pd.DataFrame(test_rows).set_index('Модель')
display(results.round(4))

baseline_rmse = results.loc['Baseline', 'RMSE']
for name in results.index:
    if name != 'Baseline':
        print(f"{name} лучше baseline: {results.loc[name, 'RMSE'] < baseline_rmse}")

linear_rmse = results.loc[main_name, 'RMSE']
print(f'Основная модель: {main_name}')
print(f'Её test RMSE: {linear_rmse:.4f}; требование RMSE < 0.70: {linear_rmse < 0.70}')
assert linear_rmse < 0.70, 'Локальный порог RMSE < 0.70 не достигнут.'

# Итоговая модель и прогноз для сдачи.
final_model = fitted_models['Linear Regression']
model = final_model
y_pred = test_predictions['Linear Regression']
```

Для каждой модели `clone` создаёт новый необученный объект с теми же настройками.
Это не копия лучшего из пяти обученных фолдов. После этого fit выполняется на полном train,
а predict — на X_test. Метрики сравнивают прогноз с y_test и не меняют модель.
`fitted_models` хранит обученные объекты, `test_predictions` — уже полученные прогнозы.

После сравнительного цикла явные строки `final_model = fitted_models['Linear Regression']`,
`model = final_model`, `y_pred = test_predictions['Linear Regression']` фиксируют результат для сдачи.
Таким образом, переменная model не остаётся последней моделью цикла, то есть бустингом.
У итогового Pipeline завершающий шаг — именно LinearRegression.

RMSE линейной модели 0.6565 ниже 0.70, MAE=0.5041 означает среднее абсолютное отклонение примерно на полбалла.
Это не «50.41% точности» и не ограничение ошибки каждого отдельного вина.
Относительное уменьшение RMSE против baseline — около 22.2%.
Test RMSE немного ниже среднего CV RMSE: это допустимо при разных проверочных объектах и финальном
обучении на большем объёме. После итоговой оценки параметры не меняются.

## Вопросы для защиты

**Почему можно использовать готовый sklearn?** Задание требует обучить и исследовать модели, а не реализовать численную оптимизацию с нуля. Алгоритм готов, параметры по нашим данным подбираются в fit.

**Почему нужен новый fit при добавлении обучающих вин?** Predict только применяет текущие веса и не меняет их. Чтобы учесть новые известные ответы, модель обучается заново.

**Почему X имеет 11 столбцов?** Это 11 измеренных характеристик. Quality отделена в y, индекс не добавлен в признаки. Число строк задаёт число вин, а не число коэффициентов.

**Зачем удалены повторы?** Чтобы точные копии не оказались в обучении и проверке одновременно. Полученные метрики относятся к уникальным наблюдениям красного вина.

**Зачем scaler в Pipeline?** Чтобы статистики в каждом CV-запуске вычислялись только по обучению этого запуска. На проверочной части применяется сохранённый transform.

**Есть ли регуляризация?** Нет. Основная модель — обычная LinearRegression без штрафа Ridge/Lasso и без полиномиальных признаков.

**Что такое baseline?** Один прогноз для всех объектов. Для RMSE используется среднее y_train, минимизирующее квадратичную ошибку константы.

**Чем MAE отличается от RMSE?** MAE усредняет модули, RMSE — квадраты с последующим корнем. Крупные ошибки сильнее влияют на RMSE. Обе метрики выражены в баллах качества.

**Почему нельзя считать качество только на train?** При fit использованы ответы этих объектов, поэтому оценка не независима. CV и test проверяют перенос на другие строки.

**Чем фолд отличается от финального test?** Фолд по очереди играет роль validation внутри обучающего пула. Отложенный test не участвует в этих пяти запусках.

**Почему в cross_validate написано test_RMSE?** Так интерфейс называет проверочную часть CV. В функцию переданы только X_train и y_train, а не финальные X_test и y_test.

**Почему scorer отрицательный?** Sklearn максимизирует scorer, поэтому ошибку представляет с минусом. В отчёте возвращён обычный положительный знак.

**Зачем сравнивать ансамбли, если требуется линейная модель?** Они входят в исходное задание и показывают возможности других алгоритмов. Итоговая model при этом явно назначена Pipeline линейной регрессии.

**Доказывает ли меньшая ошибка леса, что наша линейная регрессия не подходит?** Нет: она отдельно получила RMSE 0.6565 и выполнила локальный порог 0.70. Требование к семейству алгоритма и минимальное качество выполнены одновременно.

**Что означает коэффициент алкоголя +0.334?** В этой формуле шаг на одно стандартное отклонение алкоголя изменяет прогноз на +0.334 при фиксированных остальных входах. Это условие модели, не причинный эффект вмешательства.

**Почему коэффициенты отличаются от корреляций?** Коэффициенты учитывают все входы вместе, корреляция сравнивает только два столбца. Связанные признаки влияют на распределение весов.

**Почему feature importance не доказывает причинность?** Она характеризует использование информации моделью в наблюдательных данных. Независимого вмешательства в состав вина не было.

**Почему крайние оценки прогнозируются хуже?** Они редки, а признаки и линейная сумма могут недостаточно различать такие вина. Возможны неучтённые свойства и шум экспертных оценок.

**Можно ли удалить крупнейшие тестовые ошибки?** Нет: так изменится проверка после просмотра ответов. В отчёте все объекты сохранены.

**Почему результат скрытой проверки неизвестен?** Там другие объекты, которых у нас нет. Локальные test и CV оценивают перенос, но не гарантируют конкретный результат другой выборки.
